1. System Overview

Fluvio Language is a full-stack AI-powered language learning platform. The frontend is a React 19 SPA built with Vite, and the backend is an Express server running on Vercel (serverless). The app uses OpenAI GPT-4o and TTS-1 for AI-powered pronunciation analysis, lesson generation, conversation practice, and scenario role-play. When OpenAI credits are unavailable, the system degrades gracefully through local heuristic fallbacks — no crashes, no dead ends.

OpenAI Integration Pattern

Every OpenAI-dependent route follows the same pattern:

1. Try to get OpenAI client via getOpenAI()
   → Throws if OPENAI_API_KEY not set
2. Catch → client = null (graceful degradation)
3. Use client if available, otherwise local heuristic fallback
4. Catch API errors → try next model / fallback chain

Example fallback chains:

RoutePrimarySecondaryTertiary (local)
/api/generate-lesson-plangpt-4ogpt-4o-miniPre-written prompts by language + level
/api/companion/chatgpt-4o (via companionChatServer)—Heuristic reply generator in companionChatServer.ts
/api/companion/scenariogpt-4o (via scenarioService)—Heuristic scenario response in scenarioService.ts
/api/generate-ttstts-1—null (no synthetic TTS fallback)
/api/analyze-audiowhisper-1 + gpt-4o—Synthetic pitch/phoneme data always added

Rate Limiting

Fixed-window rate limiter keyed by IP:
  · Window: 60 seconds
  · Max requests: 20 per window (configurable via RATE_LIMIT_PER_MIN env)
  · Storage: in-memory Map (resets on server restart — Vercel serverless = per-invocation)
  · Response: 429 with Retry-After header
  · Applied to: /api/* routes only

Synthetic Audio Analysis (Local Fallback Data)

When OpenAI analysis is unavailable or as enrichment on top of GPT-4o output, the server generates plausible synthetic data:

generatePitchContour(durationSec, refText):
  → 16 time-series points comparing user_pitch vs native_pitch
  → Native: sinusoidal pattern around 180Hz
  → User: native + random offset (±45Hz, biased toward error)

generatePhonemeErrors(refText, targetPhoneme?):
  → Scans words for target phoneme or random phoneme substitutions
  → Returns: [{ phoneme, expected_word, start_ts, end_ts, detected, confidence }]
  → Typical: 0-3 errors per sentence

generateProsodyDeviations(refText):
  → Random word-stress and sentence-rhythm deviations
  → Returns: [{ type: "word-stress"|"sentence-rhythm", word, measure }]

generatePronunciationGuide(refText, targetLang, userLang):
  → Hardcoded tips per language (EN/ES/FR currently)
  → Returns: [{ segment, tip }]

6. Cross-Cutting Concerns

Fallback Chain Design

The app is designed to never crash when OpenAI credits are unavailable. Every OpenAI-dependent feature has a degradation path:

analyze-audio: Whisper + GPT-4o → 500 error with message
               (synthetic pitch/phoneme data always generated locally)

generate-tts: TTS-1 → 500 error with message
              (no synthetic fallback — audio is optional)

generate-lesson-plan: gpt-4o → gpt-4o-mini → pre-written prompts by
                      language + CEFR level (always works)

companion/chat: GPT-4o → local heuristic reply generator
                (greeting-based + template responses)

companion/scenario: GPT-4o → local heuristic scenario response
                    (pre-written scenario turns + heuristic 5-dimension scores)

TypeScript Strict Mode

The project uses npx tsc --noEmit --skipLibCheck for verification. Large generated data files (1,100 sentence arrays per language) trigger TS2590 "type instantiation is excessively deep" errors that are non-functional at runtime — these are suppressed via --skipLibCheck. The manually authored source files (server.ts, services/*.ts, components/*.tsx, App.tsx, types.ts, data/library.ts) are all type-clean.

Build Pipeline

Frontend:  npx vite build
            → dist/index.html (1.6kB)
            → dist/assets/index-{hash}.js (3MB, includes all 8 language datasets)

Server:    npx esbuild src/api/index.ts --bundle --platform=node --format=cjs
            --packages=external --sourcemap --outfile=api/index.cjs
            → api/index.cjs (2.7MB, bundled Express server)
            → api/index.cjs.map (source map)

Combined:  npm run build:node
            (runs both steps sequentially)
